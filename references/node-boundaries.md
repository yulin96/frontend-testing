# Node、Fastify 和外部边界

## HTTP 与服务

- Fastify 项目优先复用应用工厂和 `inject` 做无监听端口的请求验证，覆盖真实路由、验证、权限和错误映射；仅在适当边界替换数据库或外部服务。
- 按实际接口契约断言 HTTP 状态、业务码、关键响应字段和副作用。不要默认所有业务失败都使用非 2xx HTTP 状态。
- 隔离用户、租户或项目的场景要使用至少两个身份，检查不能读写另一方数据；只断言“返回了数组”没有验证隔离。
- 使用 `close` 等实际清理路径释放实例。HTTP adapter/mock 测试不能证明真实数据库方言、迁移执行和网络部署成功。

## 文件、上传和恢复

- 用临时目录和真实本地文件操作验证文件内容、路径边界、原子提交或失败保留；不访问用户真实数据目录。
- 覆盖当前实现中的关键失败点，例如写入失败、流错误、下载取消、部分失败后重试。只 mock 网络边界，避免把需要验证的提交/恢复逻辑也 mock 掉。
- 对失败路径同时检查错误和禁止发生的副作用。重试测试检查次数、参数和最终结果，而非只放宽等待时间。
- Mock SDK 时保留真实的重试/分片/回调协议。若依赖内部 API，明确验证对应版本；mock 通过不能代表真实 OSS/FTP 或设备成功。
- IPC 授权测试调用实际校验路径，使用允许和拒绝的 sender/main-frame 情况；不能用固定返回 true 的授权 mock 证明权限正确。

## CLI 输出与环境

- 复现用户实际运行的 shell、cwd 和相关环境变量，避免只在另一个终端环境下验证。
- 只测试可见文本时，可用 `stripVTControlCharacters` 去掉 ANSI 控制码，仍保留精确的业务数字、顺序、名称和消息。只有颜色行为相关时才额外检查转义序列。
- 涉及终端着色时，运行目标测试的普通和强制颜色环境；避免无关地重复全部测试。
- 不让测试配置导入会部署、上传或启动外部服务的业务配置。若既有命令有副作用，选择项目可支持的安全测试入口并说明差异。
- 正常退出不能替代业务成功断言；同时检查退出码、stdout/stderr 和预期产物。不要用 `|| true` 或吞掉子进程返回码隐藏测试失败。
