# Vue 与 Vitest 的针对性测试

## 测试层级

- 纯函数与无生命周期依赖的 store/composable：直接调用公共接口，精确检查输出及必要状态变化。
- 依赖 `onMounted`、`onBeforeUnmount`、`onUnmounted`、provide/inject 或 template ref 的逻辑：使用 Vue Test Utils 的小组件或宿主挂载真实 Vue 生命周期。模拟生命周期回调不能证明真实 ref 清理时机。
- 组件交互：触发真实用户入口，检查可见结果、禁用状态、emitted payload 和必要调用。避免只检查内部方法被调用，或通过直接改内部状态绕过待验证操作。
- 跨 store、路由、请求封装的行为：使用最小集成路径，不为所有依赖都设 mock。

## 高价值场景

只选择与当前功能相关的项目：

- 新实体替换：新响应缺字段时旧字段是否残留；保存目标身份是否与显示身份一致。
- 异步竞争：用可控制完成顺序的 Promise 先返回新请求、再返回旧请求，断言最终身份和字段仍正确。
- 事件与状态：业务要求每条消息触发动作时，覆盖重复相同 payload 和连续消息；不能只检查最新 ref 值变化。
- 路由历史：覆盖成功、守卫返回的导航失败和抛出异常；检查历史栈只在正确的时机变化。以项目安装的 Vue Router 契约为准，不能把任意 fulfilled Promise 当作成功。
- 生命周期：挂载、触发、卸载后再次发事件，检查必要清理和迟到回调。KeepAlive 的停用/恢复只在项目使用它时覆盖。
- loading/lock：检查成功、失败以及存在的取消/超时分支，既保证可恢复，也保留防重复提交约束。

## 运行与隔离

- 沿用当前版本支持的 API，不把单纯补测试变成框架升级。读已有 setup、aliases 和类型配置。
- 根据异步来源使用 `nextTick`、`flushPromises` 或明确的完成信号；不要用任意 sleep 掩盖竞态。所有事件触发及异步断言必须正确等待。
- fake timers 只替代时间边界；推进目标所需时间，并恢复真实 timers。Vue 更新、Promise microtask 和 timer 的顺序要反映真实流程。
- 保持 mock、stubGlobals/env、store、DOM 和 module-level 状态隔离。必要时卸载 wrapper；不要依赖其他测试先完成初始化。
- 断言组件行为时不要把目标子组件全部 stub 掉。浅挂载只适合不依赖子组件实际行为的测试。

## 证据边界

jsdom 和组件测试能证明相应状态与生命周期行为，不能证明布局、Canvas 字形位置、真实 WebView、触觉、视频自动播放或 Electron 窗口行为。需要真实浏览器时，先检查已有授权；选最短关键流程，不默认遍历页面或运行全部 E2E。
